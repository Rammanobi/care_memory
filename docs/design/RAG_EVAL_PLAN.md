## 1. Corpus: one patient replayed at day 3, 30 and 60

- **Patient.** `cm.sim.gen.generate_patients(seed=2, 40, 60)[16]` (sim token `P2-016`, base rate 0.93, pattern
  `market_day`), relabelled PT-0142. True behaviour and noisy self-report come from the generator; the truth
  (`market_weekday = Tuesday`, true misses) is recorded in the gold snapshot and used only by the evaluator.
- **Channels, deterministic.** Daily check-ins from `reported` (Telegram, web app every fifth day), free-text miss
  reasons and replies from `fixtures/text_bank.json` (English and Telugu; the market reason on market weekdays),
  chemist refills on days 0, 14, 28 and 47 (recorded the next day, so the log is bitemporal) with a refill-gap alert on
  day 44, symptom reports (days 12, 20 in Telugu, 38), Supporter visits, three doctor decisions (days 10, 33, 50),
  a Gmail doctor reply (day 21), lab slip and lab remark (days 28, 29), documents and medicines from
  `cm/jobs/seed_patient_app.py`, household screening (day 2), doctor and nurse notes (days 47, 52), a
  prompt-injection message (day 25), and a three-day trip with no check-ins (days 53 to 55, which produces a "quiet"
  event on day 56). Texts are tokenized at render time, as the index stores them.
- **Foreign patient.** PT-0203 (`generate_patients(2)[5]`) lives in the same store with its own check-ins and a cough
  report, to test isolation.
- **Replay.** `as_of(N)` is the start of sim day N (days 0..N-1 are history). An event is visible only when
  `recorded_at <= as_of` and `occurred_at <= as_of` (RAG_STRATEGY_v2 Option A predicate). Visible events: 8 at day 3,
  44 at day 30, 82 at day 60.

## 3. Metrics

| Metric | Definition |
|---|---|
| recall@5, recall@10 | share of gold events covered by the source events of the top 5/10 chunks (event-level, so comparable across chunk strategies) |
| MRR | 1 / rank of the first chunk built from a gold event |
| nDCG@10 | binary relevance (chunk has a gold event); ideal = min(10, relevant chunks in the index) |
| ctx_precision | gold events / all events behind the retrieved chunks (penalises long chunks that "contain everything") |
| abstain accuracy | answer abstains exactly when gold is empty or the question is adversarial |
| citation validity | cited `D-`/`E-` refs exist, belong to the scoped patient and are visible at as_of (hard gate 1.0) |
| groundedness | `1 - cut_ratio` from the production `cm.validator.cite_or_cut` with evidence = retrieved chunks + their events |
| answer correct | weekday / date facts present in the answer (offline extractive composer, so patterns are only stated by rollups or the live LLM) |
| temporal leakage | retrieved chunks with `recorded_at` or `occurred_at` after as_of (hard gate 0) |
| isolation | retrieved chunks of another patient (hard gate 0) |
| latency | retrieval p50/p95 ms per question; index build ms |
| embedding cost | new (uncached) texts, tokens and USD; fake embedder = 0 |

Objective = 0.35 recall@10 + 0.25 MRR + 0.15 nDCG@10 + 0.15 ctx_precision + 0.10 abstain accuracy, averaged over
the as_of days. Any leakage, isolation violation or citation validity below 1.0 disqualifies a config. Winner = the
cheapest config within 0.02 of the best objective (no rerank < rerank, BM25 < embeddings, smaller top_k, fewer chunks).

## 4. Experiment grid

size {128, 256, 384, 512} x overlap {0, 50, 100, 200} x strategy {fixed, sentence, event, dynamic} x mode
{bm25, vector, hybrid} x rerank {none, llm} x top_k {4, 8, 12}; overlap >= size is skipped (1,080 valid configs).

- Default search: one-factor-at-a-time around the baseline `event/s256/o50/hybrid/none/k8` (size and overlap are swept
  under `fixed` and `sentence`, where they matter), then the cartesian product of the best two values per factor.
  `--search full` runs the whole grid; on the fake embedder both searches pick the same winner.
- Strategies in the memory backend: `fixed` and `sentence` chunk the patient's visible timeline as one document with
  `cm.rag.chunk.chunk_text`; `event` is one chunk per rendered event; `dynamic` is event chunks + closed-week rollups
  (rollups only for weeks that ended before as_of, never revised). Query rewrite is a small English+Telugu lexicon
  (no LLM), "last/latest" adds a recency boost, "last week" a 7-day window, pattern words boost weekly rollups.
- Fusion: BM25 (`cm.rag.retrieve.bm25_scores`) and cosine legs, RRF k=60 (`cm.rag.retrieve.rrf`).
- Rerank `llm`: the real `cm.rag.rerank.llm_rerank`. Offline its model is a deterministic coverage stand-in
  (`FakeRerankModel`, answers the same prompt), so offline "llm" numbers measure the plumbing, not the WORKER model.
- Embeddings: `CappedEmbedder` dedups by text over the whole run, persists `out/rag_eval/embed_cache.json` for real
  models, estimates cost before each call and stops at $0.50; only totals are printed.
- Answers: offline, the extractive Ask-box path (RAG_STRATEGY_v2 5.2: top 3 quoted, dated chunks with `[D-..]` and
  `[E-..]` refs; abstain when no top chunk carries the question's key terms, when a pattern question has under 14 days,
  and refuse on injection or another patient's code). `--live` (or `python -m cm.eval.rag_live`): answers come from
  `cm/api/routers/query.py` `compose_answer`, the same function the Ask box calls (pre-abstain rules, `RAG_SYSTEM`
  with EN+TE few-shot, temperature 0, `cut_to_cited`, output guard), over production-shaped retrieval (events + week
  cards, small-corpus switch at 60 chunks, else hybrid top 12 with the 2 best chunks first). WORKER = deepseek flash;
  the `ai_eval.ASK_RUBRIC` JUDGE runs only on answered cases, against the chunks the answer cites. Replies are cached
  by prompt hash (`out/rag_eval/live_cache.json`): `--only` and `--rescore` re-score with no new spend. Governor cap
  $1.00 per run; skipped cases (cap reached) are reported, never scored as failures.

## 6. Results

and Telugu questions rely on the lexicon) and "llm" rerank is the deterministic stand-in. What it does show today:
zero temporal leakage and zero foreign chunks in every config, citation validity and groundedness 1.0, correct
abstention on all 13 day-3 unanswerable or adversarial questions, one-chunk-per-event beating whole-timeline windows
on context precision, and top_k 8 beating 4 (recall) and 12 (precision). The extractive composer cannot state a
weekday pattern, so answer_correct is 0.5 at day 30 and 60 until rollups or the live LLM state it. Re-run with
`--embedder openai --live` before quoting numbers in the demo.

Root causes of the first run's low numbers: (1) budget-cap errors were scored as failed answers (41 of 66 rows); (2) the
harness had its own composer, without the Ask box's pre-abstain rules (pattern before day 7, another patient's code)
or retrieval shape (no small-corpus switch, no week cards in the winning `event` config); (3) abstention was read with
a substring detector (a Telugu "no information about a delay" sentence after a correct refill date counted as abstain);
(4) the judge saw the harness's dated abstain text and judged it "unsupported", and judged abstentions at all;
(5) groundedness used weaker number evidence than the route (digits inside ISO dates and "14-day" were not evidence).

Day 60 t01 (Telugu weekday question), retrieval bug and fix. Reproduced offline with FakeEmbedder and with the cached
real embeddings (identical outcome): top 12 held 8 weekly cards for bm25 alone and 0 for vector and hybrid. Cause: the
cards are English and the question is Telugu, so the vector leg ranks them 59th to 76th of 90 (cosine ~0.1 against ~0.2 for
Telugu "dose taken" event lines), while bm25 ranks them 5th to 12th; equal-weight RRF then lets the event chunks, which
appear high in the vector leg and also in bm25, outscore every card (a 1.15 pattern boost in the harness was too small).
The production path (`cm.rag.retrieve`) had no rollup handling at all, and with no query expansion a Telugu question has
no lexical overlap with the cards. Fix: `search_patient_memory(..., pattern=True)` (passed by
`cm.tools.memory_search` for pattern questions) guarantees a quota of 4 weekly cards (`with_rollup_quota`, taken from the
whole prefiltered pool, best fused score then newest, placed after the two best hits, paid for by the lowest-ranked event
chunks); the live harness applies the same function. Result: t01 day 60 now answers correctly (Tuesday, citing
week cards) with 4 weekly cards in the top 12; 4 of 4 expected-fact questions correct on day 60. Card text did not
change. Other pattern questions (q01 day 30 and 60, day 3) already had their cards and are unchanged.
Remaining misses: day 30 q08 (the lab slip says a test was done but not what it said; the model abstains); day 30 q14
and day 60 t04 each fail the judge (a date stated as 2026-01-05 where the card says 2026-01-06, and a record date
conflated with a visit weekday: model errors, not retrieval); day 30 q10 counts as correct only through the
negative_ok gold (a cited "no, at most 1 day without check-in" is right when no quiet event exists).

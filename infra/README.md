# infra/ runbook (Cloud Run, asia-south1)

Run from `caremem/` in Git Bash or Cloud Shell after `gcloud auth login` and `gcloud config set project <project>`.
Every script sources `vars.sh`: set `PROJECT` (default `caremem-hack`), `REGION` (`asia-south1`) and `DOMAIN` (apex, no scheme).
`DRY_RUN=1 bash infra/<script>.sh` prints the gcloud calls and runs nothing (safe anywhere). Never print or paste secret values.

## Order

| # | Command | Notes |
|---|---|---|
| 0 | edit `infra/env/*.env.yaml` | project/bucket names if not `caremem-hack`; `<domain>` is substituted from `DOMAIN` at deploy |
| 1 | `bash infra/00_project.sh` | enables APIs (compute, run, sqladmin, secretmanager, cloudtasks, cloudbuild, artifactregistry, pubsub, gmail, calendar-json, cloudscheduler, logging, monitoring), Artifact Registry `cm`, bucket |
| 2 | placeholder `gcloud run deploy cm-api --image=us-docker.pkg.dev/cloudrun/container/hello --region=$REGION --allow-unauthenticated` | gives the NEG a service |
| 3 | `DOMAIN=example.org bash infra/85_lb.sh` | IP, NEG, URL map, one managed cert, HTTP->HTTPS. Add the printed A records at your DNS host now: the cert waits on DNS (15 min to hours) |
| 4 | `bash infra/10_iam.sh` | service accounts and roles |
| 5 | `bash infra/30_secrets.sh` | creates secrets, generates random ones, lists missing REQUIRED names. Add values via stdin: `printf %s "$V" \| gcloud secrets versions add NAME --data-file=-` |
| 6 | `bash infra/20_sql.sh` | Cloud SQL (10-15 min) |
| 7 | `bash infra/40_pubsub.sh`, `bash infra/50_tasks.sh` | topics, queues |
| 8 | build and push the image | `gcloud builds submit --tag $REGION-docker.pkg.dev/$PROJECT/cm/cm:<tag>` |
| 9 | `DOMAIN=example.org IMAGE=<image:tag> bash infra/60_deploy.sh` | worker, api, jobs `cm-migrate`, `cm-seed`. Secrets without a value are skipped (listed by name) |
| 10 | `bash infra/80_webhooks.sh` | backup, migrate, Telegram webhook on the run.app URL, health check. Stop the laptop `tg_poll` first |
| 11 | `gcloud run jobs execute cm-seed --region=$REGION --wait` | demo data (needs `DEMO_USER_PASSWORDS`) |
| 12 | `bash infra/70_scheduler.sh` | `/tasks/drain-outbox` every minute, `/tasks/checkins` daily 07:30 IST; `OPTIONAL_NIGHTLY=1` adds nightly |
| 13 | when the cert is ACTIVE: `DOMAIN=example.org bash infra/90_telegram_webhook.sh` | moves the webhook to the domain |
| 14 | `bash infra/tests/smoke.sh` | checks |

## Secret names (values never in the repo)
Required: `DEEPSEEK_API_KEY`, `OPENAI_API_KEY`, `TELEGRAM_BOT_TOKEN`, `DEMO_USER_PASSWORDS` (added by hand);
generated by `30_secrets.sh`: `TELEGRAM_WEBHOOK_SECRET`, `JWT_SIGNING_KEY`, `PII_MASTER_KEY`, `DB_PASSWORD_APP|ENGINE|READER|ADMIN`.
Optional: `LANGSMITH_API_KEY`, `GMAIL_OAUTH_CLIENT_JSON`, `GMAIL_REFRESH_TOKEN`.
The code reads `DB_PASSWORD`; `60_deploy.sh` maps it from `DB_PASSWORD_APP` (api, worker) or `DB_PASSWORD_ADMIN` (jobs).

## Entrypoint (`python -m cm <command>`)
`api`, `worker` (uvicorn on `$PORT`), `migrate`, `drain-outbox` (one pass), `sweeper` (stub, exits 0), `nightly --patient X`, `reminders`, `seed`, `eval`.
Env style also works: `CM_ROLE=job CM_JOB=migrate`.

## Database on Cloud Run
`DB_HOST=/cloudsql/<project>:<region>:cm-pg` (unix socket) with `DB_USER` `cm_app` (api, worker) or `cm_admin` (jobs).
If `DB_HOST` is unset, `CLOUD_SQL_INSTANCE` is turned into `/cloudsql/<instance>`.

## Quiet hours (21:00-07:00 IST)
Reminders are deferred at night. For a night demo set `DEMO_IGNORE_QUIET_HOURS=1` on cm-api and cm-worker; it is honoured only when `CM_ENV` is `dev` or `demo`, never `prod`. Turn it back to `0` afterwards.

## Other env names (placeholders in `api.env.yaml`)
`COOKIE_SECURE=1`, `CORS_ORIGINS`, `CM_ALLOWED_HOSTS`, `CM_COOKIE_DOMAIN` (leave empty), `PUBLIC_BASE_URL`.
